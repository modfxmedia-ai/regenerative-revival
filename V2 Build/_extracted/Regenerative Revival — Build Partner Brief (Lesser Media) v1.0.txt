1.  PROJECT OVERVIEW

Regenerative Revival is rebuilding its digital presence around a dual-hub architecture that reflects how the business actually operates: a regenerative medicine concierge funnel on one side (consult-led, never selling stem cells or exosomes online), and a telehealth marketplace on the other (self-serve peptides, HRT, NAD+, and supplements delivered through the Wizlo platform). Both hubs live under one brand, share one patient record, and route every lead, order, and prescription into a single source of truth.

This brief covers the complete build of that system end-to-end: the new public-facing marketing site, full white-labeled integration with the Wizlo platform and products marketplace (58 active SKUs), and a fully wired Tyriacore CRM instance at tyriacore.app that captures every patient, lead, order, and subscription from first click through fulfillment.

The site is scoped as the Phase 1 launch build. Phase 2 items (For Providers page, affiliate tracking, loyalty tiers, co-branded partner pages, multilingual support) are explicitly carved out and will be handled separately once Phase 1 is live.

LAUNCH OBJECTIVE
Put the dual-hub positioning live, make both consult flows work end-to-end, and ensure every patient interaction — regen consult, telehealth intake, marketplace order, Rx refill — is captured in Tyriacore with complete source attribution and pipeline tracking.

KEY CONSTRAINTS
- LegitScript compliance required across all telehealth-facing surfaces
- Category II medications must stay off public navigation (concierge-only interstitial pages)
- HRT held until Steve's (Wizlo) automation is ready — exclude from MVP catalog
- Hims is the design reference for polish and premium feel; preserve clinical credibility

2.3  TYRIACORE CRM BUILD-OUT (tyriacore.app)

Tyriacore is the single source of truth for Regenerative Revival. Every patient record, every lead, every marketplace order, and every clinical event is captured here with complete source attribution. The build-out includes CRM configuration, webhook infrastructure, and the bi-directional sync architecture between Tyriacore and every adjacent system.

CRM configuration:
- Contact/patient record schema defined and deployed
- Custom fields mapped for RR-specific data: product category, dosage, consult source, regen vs telehealth path, NP assigned, referring partner
- Two pipelines built: Regenerative Consult Funnel and Telehealth Intake Funnel
- Stages defined for each pipeline with automation hooks at each stage transition
- Automated tag and list assignment based on product category (GLP-1, peptide, NAD+, sublingual, capsule, regen consult, HRT intake)

Regenerative consult funnel — pipeline stages:
Consult requested → Consult scheduled → Consult completed → Qualified / Not qualified → Converted / Nurture
- Source attribution captured on every lead (ad campaign, organic, referral, seminar, influencer affiliate)
- Automated SMS/email notifications on stage transitions via GHL

Telehealth intake funnel — pipeline stages:
Intake submitted → Provider review → Qualified / Declined → Rx sent → Shipped → Delivered → Refill due → Reordered / Churned
- Product SKU, dosage, quantity, and refill schedule captured on every order record
- Refill-due automation triggers 7 and 14 days before expected reorder

Webhook and data-flow infrastructure:
- Website forms → dual-write to GHL and Tyriacore with source tagging
- Wizlo intake submissions → Tyriacore patient record with full form payload
- Wizlo marketplace orders → Tyriacore order record with SKU, dosage, patient match
- Wizlo e-Rx events → Tyriacore timeline events on the patient record
- GHL regen consult events → Tyriacore with pipeline stage sync
- Error handling and retry logic on every webhook endpoint
- Admin dashboard view in Tyriacore showing live funnel health for both pipelines


2.4  CROSS-SYSTEM INTEGRATIONS

The four systems — website, Wizlo, GHL, Tyriacore — are wired together so no data lives in only one place and every handoff is observable.

| Source | Destination | Data & Trigger |
| Website forms | GHL + Tyriacore | Regen consult, newsletter, partner applications, contact — dual-write on submit with UTM and source tags. |
| Unified Consult Router | GHL or Wizlo | Two-question qualifier routes to GHL (regen path) or Wizlo intake (telehealth path) based on answers. Audit log written to Tyriacore. |
| Wizlo Intake | Tyriacore | Full form payload written to patient record. Creates new contact if not matched, updates if matched on email/phone. |
| Wizlo Marketplace | Tyriacore | Order record created with SKU, dosage, quantity, amount, provider, and refill schedule. |
| Wizlo e-Rx | Tyriacore | Rx sent / shipped / delivered events written as timeline events on patient record. |
| GHL | Tyriacore | Regen consult stage transitions sync to mirrored pipeline in Tyriacore. Notes, tags, and assigned-user fields sync bi-directionally. |

7.  REVISIONS & CHANGE MANAGEMENT

7.1  Revisions included
- One (1) bundled revision round per page after initial build, delivered in Week 2, 3, or 6 depending on page
- Revisions must be consolidated into a single document per page — rolling individual changes are treated as out-of-scope
- Revision scope is limited to adjustments within the approved design direction and copy framework — fundamental redirection ("actually, let's change the whole hero concept") is a change request

7.2  Change requests
- Any work outside this brief is handled via written change request between ModFX and Lesser Media, approved before work proceeds
- Scope additions that move Phase 2 items into the Phase 1 launch add 1 week of timeline per page
- New product groups or new Wizlo integrations beyond the 58 SKUs noted in Section 2.2 are handled as change requests

7.3  Change-of-direction policy
If the end client decides mid-build to change fundamental architecture (e.g., swap the stack, change the dual-hub structure, migrate off Tyriacore), ModFX will coordinate with Lesser Media on a project restart. Work completed to that point is not redone under the original engagement.
